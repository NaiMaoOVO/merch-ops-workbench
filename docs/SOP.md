# 海外商品运营工作台 SOP 教程

> 适用版本 v0.1+ · 本地优先 · 数据只存本机浏览器 · AI 仅作辅助假设，需人工确认
> 本文档为唯一事实来源（docs/SOP.md），功能更新后同步更新此页并重新发布到飞书。

## 一、首次准备（约 5 分钟）

### 1.1 环境要求
- Node.js ≥ 18（终端执行 `node -v` 能看到版本号即可）。
- 浏览器：Chrome / Edge 桌面端（本地存储依赖较新内核）。
- 操作系统不限；Windows / macOS 均可。

### 1.2 获取与启动
1. 克隆仓库并安装依赖：
   ```bash
   git clone git@github.com:NaiMaoOVO/merch-ops-workbench.git
   cd merch-ops-workbench
   npm install
   ```
2. 启动开发服务：`npm run dev`，浏览器打开 http://127.0.0.1:5174。
3. 端口冲突排查：提示端口占用时，先关闭占用 5174 的旧进程再启动（启动脚本使用 strictPort，不会自动换端口）。

### 1.3 （可选）配置 AI 接口
- 入口：「设置与数据管理」→ AI 接口区域。
- 字段说明：
  - 接口地址：OpenAI 兼容的 base 地址（如 `https://api.openai.com/v1`），系统自动补全 /chat/completions；
  - 模型名：如 `gpt-4o-mini` 等，以你的服务商为准；
  - API Key：仅保存在本机 localStorage，**不包含在任何导出备份里**。
- 点「测试连接」验证；不配置 AI 不影响任何本地分析能力。

### 1.4 首次学习路径
进入「教程与帮助」→「用示例数据开始练习」，跟随 6 步引导完整走一遍分析链路，再开始真实数据。

## 二、每周商品数据分析 SOP（核心流程）

### STEP 0 新建或复制项目
- 新建：首页「新建分析项目」。
- 复制上周：「历史项目」→ 找到上周项目 →「复制」，字段映射与规则配置会一并沿用。
- 项目字段：名称（建议含周次）、周期、站点、品类范围。创建后导入的数据副本与配置一起存本机，刷新页面可续做。

### STEP 1 导入数据
- 入口：「商品数据分析」→ 导入 Excel / CSV。
- 支持多文件、多工作表一次导入；单表超过 10 万行会自动截断并明确提示。
- 容错策略：单个文件解析失败只提示该文件名和原因，其余文件正常导入。
- CSV 注意：首列表头若出现乱码前缀，系统已自动剥离 UTF-8 BOM；仍异常请检查文件编码是否为 UTF-8。

### STEP 2 数据质量检查
- 查看三个指标：行数、字段数、空值列数。
- 「发现 N 个需要留意的问题」重点看空值列：核心指标列（曝光/点击/支付/销售额）出现空值时，优先回源补数或在报告中备注原因，不要静默忽略。

### STEP 3 多表匹配（VLOOKUP 式）
- 示例模式：演示 销售 → 商品 → 品类 → 供应商 的连续匹配过程。
- 真实导入 ≥2 张表后出现「匹配编辑器」：
  1. 选主表（通常是订单/销量明细）；
  2. 选关联表与关联键——系统按列名相似度推荐（同名或去符号后一致），纯中文列名务必人工确认；
  3. 查看预览四项指标：输出行数 / 未匹配主表键 / 重复副表键 / 行数膨胀。
- 判定标准：重复键 > 0 说明副表该键不唯一，继续匹配会造成行数膨胀，应先在数据源去重或改用一对一维表。

### STEP 4 字段映射确认
系统把原始列名对齐到以下标准字段（自动识别 + 可手动覆盖）：

| 标准字段 | 含义 | 常见原始列名示例 |
| --- | --- | --- |
| productId | 商品唯一标识 | SKU、商品ID、item_id |
| date | 统计日期 | 日期、统计日、date |
| impressions | 曝光量 | 曝光、展现、impressions |
| clicks | 点击量 | 点击、clicks |
| paid | 支付件数 | 支付件数、付款件数、paid |
| salesAmount | 销售额 | 销售额、GMV、sales |
| category | 品类 | 品类、类目、category |

- 下拉框留空 = 使用自动识别结果；同列重复映射或缺必选列会被拦截并提示。
- 低置信度的自动识别会出现提醒，请人工核对后再进入分析。

### STEP 5 分析与诊断
- 筛选栏：日期范围 + 品类，实时生效（显示「当前 N / 总 M 行」）；趋势图需要 ≥2 天数据才会出现。
- 默认诊断维度：曝光量、点击率、支付转化率等相对均值的偏离；每条异常卡片给出证据数值与建议动作。
- 自定义规则（可选）：选指标（点击率/转化率/销售额/客单价…）+ 比较方式（< ≤ > ≥）+ 阈值或分位数 → 添加。示例：点击率 < 0.6% 且曝光量高的商品列为高优先级核查对象。
- 转化闭环：异常卡片一键「转日常任务」「转供应商问题」；任务完成后，首页「待确认异常」计数自动扣减，全部解决时显示「已全部解决 ✓」。
- AI 假设（可选）：点「AI 原因假设」→ 核对脱敏预览（供应商/商品ID 等文本列已隐藏，仅保留数值与日期，默认抽样 20 行）→ 手动点「确认发送」。模型返回内容一律标注「辅助假设 / 待审核」，未经人工验证不得写入报告结论。

### STEP 6 透视、漏斗与导出
- 自动生成：品类透视条形图 + 曝光 → 点击 → 支付漏斗。
- 「导出 Excel」包含四个工作表：异常商品 / 品类透视 / 漏斗汇总 / 匹配明细，可直接作为周报附件。

### STEP 7 周报产出
- 报告页支持「双周期对比」表；点击「AI 执行摘要」后先查看脱敏字段预览，再确认发送，返回内容会以「待审核摘要」写入可编辑模块。
- 周报结构可通过「存为模板」保存，之后在报告模块区直接套用。
- 「周报与报告」自动绑定当前项目（标题 / 周期 / 数据来源），诊断部分读取项目真实分析摘要；没有项目数据时会显示示例并明确标注「示例」。
- 支持：模块级编辑、撤销 / 重做、AI 内容逐条确认；草稿按项目自动保存，下次打开自动恢复。
- 导出前看完整性检查提示（未确认的 AI 假设 / 周期缺失 / 空模块），再选择 Markdown / HTML / Word / Excel / PDF 任一格式导出。

## 三、标题优化 SOP

1. 「标题优化」→ 设置目标语言与禁用词（禁用词支持中英文逗号、顿号分隔）。
2. 点「重新生成」用本地模板产出候选；需要 AI 时点「AI 候选」→ 核对脱敏预览 → 手动确认发送（结果标注 AI 辅助 + 待审核）。
3. 逐条审核三项校验：长度、禁用词命中、事实一致性；粉色高亮词表示相比原标题新增的词，用于快速定位改动。
4. 批量操作：勾选多条 →「通过所选 / 退回所选」。
5. 「导出已通过」仅导出已通过项（JSON 格式），供上架工具消费。

## 四、供应商问题 / 日常任务 / 热点 SOP

- **供应商问题**：填写类型 / 优先级 / 截止日 / 自定义字段；状态流转：待确认 → 处理中 → 等待供应商 → 已解决 → 已关闭；侧栏角标实时显示未关闭数量。
- **日常任务**：支持筛选 / 逾期标记 / 延期；来自异常诊断的任务会标注所属项目；顶栏通知徽章 = 逾期任务数 + 未关闭问题数（逾期定义：截止日早于今天且状态非完成/取消）。
- **热点与选品**：手动记录关键词 / 来源链接 / 截图备注；状态流转：待验证 → 已验证 → 已转化 → 已归档；可关联品类与商品。

## 五、历史项目与备份 SOP

### 5.1 两种备份的区别

| 能力 | 项目备份 | 全量备份（推荐定期做） |
| --- | --- | --- |
| 覆盖范围 | 仅项目及其配置 | 本地全部记录：项目、任务、异常、热点、报告草稿 |
| 冲突策略 | 冲突项目另存副本 | 同键覆盖写入（导入前有明细确认弹窗） |
| API Key | 自动剥离 | 不涉及（Key 不在工作台命名空间内） |

### 5.2 操作要点
- 对比：勾选两个项目 → 表格逐项对比（周期 / 站点 / 进度 / 表数量等，变更高亮）。
- 删除：同时清理该项目报告草稿；有确认弹窗且不可恢复，删除前建议先全量备份。
- 容量提示：历史页顶部显示本地占用估算；超过约 3 MB 时会出现「建议先导出全量备份」提示。
- 换机迁移：旧机「全量备份」下载 JSON → 新机启动后「全量恢复」选择该文件 → 按提示确认 → 刷新页面生效。

### 5.3 数据存储与容量（IndexedDB）

- 从 v0.1 起，工作台数据自动迁移到浏览器 **IndexedDB** 存储，容量上限从约 5MB 提升到 GB 级，可放心按天积累数据。
- 迁移完全自动：首次打开新版本时进行，无需任何操作；旧 localStorage 会保留 **14 天**作为回滚保险，到期且与云端内容一致时自动清理。
- 若 14 天内发现任何异常，可回退到旧版本，历史数据原样可用。

### 5.4 一键使用包（给朋友/同事的零安装分发）

- 维护者执行 `npm run pack:portable`，生成 `release/海外商品运营工作台-一键使用包.zip`（约 300KB）。
- 包内：`工作台.html`（纯前端单文件，离线可用）+ Mac/Windows 双击启动器 + 使用说明。
- 接收方：解压 → 双击 `工作台.html`（或平台对应启动器）→ 浏览器打开即用，无需安装 Node。
- 数据同样只存在接收方本机浏览器；如需回传分析结果，用报告导出功能即可。

## 六、常见问题

| 问题 | 处理 |
| --- | --- |
| 启动报端口占用 | 关闭旧的 5174 进程后重新 npm run dev |
| CSV 首列表头异常 | 系统已自动剥离 UTF-8 BOM；仍异常请检查文件编码 |
| 刷新后数据还在吗 | 在。导入副本随项目保存在本机 localStorage |
| 报告显示示例数据 | 说明还没有带分析摘要的本地项目；先完成一次导入分析即可 |
| 趋势图不出现 | 需要筛选后仍有 ≥2 个不同日期的数据 |
| 如何查看单个商品 | 在异常卡片点击「查看商品详情」，查看当前筛选范围内的曝光、点击、支付和销售额汇总；点击返回即可回到分析列表 |
| 如何启用自动备份 | 每次打开工作台会检查最近一次自动备份，超过 7 天会自动下载一份全量 JSON；仍建议在历史项目页手动导出 |
| 如何使用循环任务 | 新建日常任务时选择每天、每周或每月，任务完成且到期后会自动生成下一期 |
| 如何切换深色模式 | 点击顶栏月亮/太阳按钮，偏好会保存在本机；打印/PDF 会自动使用白底打印样式 |
| 映射下拉里找不到某列 | 该表可能缺少对应列；先检查 STEP 01 选择的数据表 |
| 透视图 / 漏斗为空 | 通常因为品类或指标列全为空，回 STEP 04 修正映射 |
| AI 调用失败 | 检查接口地址 / 模型名 / Key 与网络；本地分析不受影响 |
| 清空某项目全部数据 | 历史项目 → 删除（含草稿）；或浏览器清除站点数据 |
| 换电脑怎么迁数据 | 见第五章全量备份流程 |
